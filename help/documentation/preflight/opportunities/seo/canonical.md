# 표준 감사

**표준** 감사에서 페이지의 표준 링크를 검토합니다. 정식 링크는 페이지 콘텐츠의 기본 URL 이름을 지정하는 페이지 `<head>`의 `<link rel="canonical">` 태그입니다. 감사는 누락되었거나, 잘못 설정되었거나, 페이지 자체가 아닌 다른 위치를 가리키는 표준 링크에 플래그를 지정합니다.

## 왜 중요한가

두 개 이상의 URL에서 동일한 컨텐츠를 접할 수 있습니다(예: 뒤쪽 슬래시가 있거나 없거나, 추적 매개 변수가 있거나, 대문자가 다른 경우). 별도의 설명이 없는 한 검색 엔진은 각 URL을 별도의 페이지로 처리합니다. 정식 링크는 원하는 URL을 알려줍니다. 중복 항목을 그룹화하고, 한 URL에서 인바운드 링크와 같은 순위 신호를 결합하고, 검색 결과에 해당 URL을 표시하는 데 도움이 됩니다.

잘못된 표준 링크는 전혀 없는 것보다 더 나쁠 수 있습니다. 검색 엔진은 신뢰할 수 없는 표준 링크(예: URL이 없는 링크, `<head>` 외부에 있는 링크 또는 동의하지 않는 태그 중 하나)를 무시할 수 있습니다. 다른 페이지를 가리키는 표준 링크는 검색 엔진에 해당 페이지를 대신 표시하도록 요청하여 페이지를 검색 결과에서 제외할 수 있습니다.

## 감사 확인 사항

감사는 다음 세 가지 영역에서 문제를 확인합니다.

* **페이지에 하나의 표준 링크가 있는지 여부:** 표준 링크가 없거나 페이지에 둘 이상의 표준 링크가 있는지 여부. 검색 엔진이 모든 URL을 무시할 수 있으므로 서로 다른 URL을 가리키는 여러 표준 링크는 별도로 보고됩니다.
* **태그가 올바르게 설정되었는지 여부:** 태그가 `<head>` 외부에 있거나, `href` 특성이 없거나 비어 있거나, 검색 엔진에서 해당 특성을 무시할 수 있는 `hreflang`, `media` 또는 `type`과(와) 같은 특성을 포함합니다.
* **URL이 올바른지 여부:** 정식 URL이 절대 URL이 아닌 상대 URL이거나, 경로 또는 쿼리 문자열에 대문자를 포함하거나, 페이지와 다른 프로토콜(`http://` 또는 `https://`)을 사용하거나, 편집 중인 페이지와 다른 페이지를 가리킵니다.

## 표준 URL을 비교하는 방법

Preflight는 일반적으로 프로덕션 사이트와 다른 호스트를 사용하는 미리보기 페이지에서 실행됩니다. 모든 미리보기 페이지에 플래그를 지정하지 않기 위해 감사는 표준 URL의 호스트를 페이지의 호스트와 비교하지 않습니다. 정식 링크가 페이지 자체를 가리키는지 확인하는 경우 URL의 경로만 비교되므로 `https://www.example.com/products/shoes`이(가) 미리 보기 페이지 `/products/shoes`과(와) 일치합니다. 경로에 있는 후행 슬래시 및 문자 대소문자는 이 검사에 대한 차이로 계산되지 않습니다.

## 알려진 제한 사항

* **다른 도메인:** 미리 보기 호스트가 프로덕션 사이트와 항상 다르기 때문에 다른 사이트를 가리키는 표준 URL은 Preflight로 플래그가 지정되지 않습니다. 표준 URL의 도메인이 예상과 같은지 확인합니다.
* **HTTP `Link` 헤더:** Preflight는 HTTP `Link` 헤더가 아닌 표준 태그만 확인합니다. 헤더에만 표준 URL을 설정하는 페이지에는 표준 링크가 없는 것으로 보고됩니다.

## 해결 방법

감사에서 기회가 발견되면, 각 기회는 문제와 권장 변경 사항을 설명합니다. 대부분의 경우 페이지에는 `<head>`에 페이지 자체를 가리키는 소문자 경로를 가진 절대 URL이 있는 정식 링크가 하나만 있어야 합니다. 페이지가 의도적으로 다른 페이지를 표준 버전(예: 복제 또는 프린터 친화적 사본)으로 가리킨 경우 그대로 둘 수 있습니다. 감사에서 계속 보고합니다. 영업 기회를 검토하고 해결하는 방법은 [Preflight에서 결과 감사](../../audit-results.md)를 참조하세요.
